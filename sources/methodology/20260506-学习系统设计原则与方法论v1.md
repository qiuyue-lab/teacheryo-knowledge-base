# 学习系统设计原则与方法论 v1

**提炼者：** TeacherYo  
**来源：** 基于荻荻素材的第一次完整学习系统设计实践  
**定位：** 这是后续打磨角色/生产流水线的核心方法论文档，会持续迭代

---

## 一、底层理念：学习系统 ≠ 内容重新排列

### 传统课程的隐含假设

传统课程（不管是视频、PPT还是图文）背后有一个共同假设：**"我把东西讲清楚了，你看了，你就会了。"** 这个假设把学习等同于信息传递。

但我们知道：**理解无法被直接传递，它只能被自己建构。** 你看再多遍别人怎么做的，你不做一次，你就不会。你听再多次"角色要从缺口出发"，你不去分析自己的缺口，这句话对你就是一个空洞的概念。

### 学习系统的核心假设

学习系统的假设完全不同：**学习是一段被设计过的"经历"。** 设计者的工作不是"把内容讲清楚"，而是"设计一个让学习者自己走到那个认知的路径"。

这意味着：
- 内容的价值不在于"信息量"，而在于"它在什么时机出现"
- 老师的价值不在于"讲得好"，而在于"知道学习者在哪里会卡住、在哪里需要被冲击"
- 学习的核心不是"我给你什么"，而是"你经历了什么"

### 信息传递的价值已经被AI打到地板

现在任何一份分享录音，AI三分钟就能总结成结构化的要点。如果你的课程核心价值是"帮你把知识整理清楚"，那AI比你做得更快更好。

课程平台真正能提供的、AI做不到的价值是：**把"别人的经验"转化为"你自己的经历"。** 这就是学习系统要做的事情。

## 二、设计原则

### 原则1：先体验，再讲概念

**错误做法：** 开篇定义"什么是角色系统"，然后举例说明。  
**正确做法：** 先让学习者暴露自己的需求（写下困境），再让他体验到普通方式的局限（问AI发现答案很泛），然后在他"觉得缺了点什么"的时候，再引入概念。

**底层逻辑：** 概念只有在学习者有了"需要被命名的感受"之后才有意义。如果学习者还没有那个感受，你给他概念只是在增加他的记忆负担。

**在荻荻案例中的体现：** 模块一和二不讲任何关于角色系统的概念。学习者先写下自己的困境，再体验了"问一个AI得到泛泛的回答"，然后看到荻荻的三个角色给出完全不同的视角——此时"多视角协作"这个概念不需要你讲，学习者自己就明白了。

---

### 原则2：学习者的真实问题贯穿全程

**错误做法：** 开头让学习者写一个问题"热热身"，后面的内容跟这个问题无关。  
**正确做法：** 模块一写下的困境，在模块二中被用来"试问AI"，在模块三中被用来"分析缺口"，在模块四中被用来"捏角色并测试"，在模块五中被用来"反思角色的局限"，在模块六中被用来"规划角色团队"。

**底层逻辑：** 学习者只关心跟自己有关的事。如果你的内容跟他的真实处境无关，他就是在"看别人的故事"。只有当他自己的问题被不断深化和重新审视的时候，他才是在"学习"。

**技术实现要点：** 学习系统需要记住模块一中学习者写的内容，在后续模块中引用它。这不是装饰，这是学习路径的核心线索。

---

### 原则3：老师的素材是"参照"，不是"教材"

**错误做法：** 把荻荻的分享整理成教程："第一步做什么，第二步做什么。"  
**正确做法：** 荻荻的经验在学习者需要的时候出现，作为"原来别人也是这么想的"或"原来还可以这样"的参照。

**底层逻辑：** 教材让人模仿，参照让人反思。模仿只能复制表面行为，反思才能产生属于自己的认知。

**嵌入时机的判断标准：**
- 学习者刚写完自己的困境 → 展示荻荻的困境，制造共鸣（"我不孤单"）
- 学习者刚体验了局限 → 展示荻荻的做法，制造冲击（"原来可以这样"）
- 学习者刚完成一个任务 → 展示荻荻的进一步思考，提供深化（"还可以更深"）
- 学习者正在动手做 → **不展示任何参照**，让他用自己的认知来行动

**特别注意：** 模块四（动手环节）故意不给任何荻荻的参照。因为参照在动手阶段会变成模仿。学习者需要在没有参照的情况下，用前面积累的认知独立判断。

---

### 原则4：最反直觉的洞察放在实操之后

**错误做法：** 一开始就告诉学习者"你需要一个反对你的角色"。  
**正确做法：** 让学习者先捏了一个"盟友型"角色并且用了一轮之后，再问他"你有没有发现它总是支持你？"

**底层逻辑：** 反直觉的洞察只有在学习者亲身碰到了那个"直觉"之后才有冲击力。如果学习者还没体验过"角色总是顺着我说"这个问题，你告诉他"需要对立面角色"就只是一个空洞的建议。

**排序原则：** 先让学习者用"正常"的方式做一遍，碰到问题，然后再给出反直觉的思路。"先碰壁、再开窗。"

---

### 原则5：框架工具从案例中自然浮现

**错误做法：** 先给框架（"角色设计有三层：能力、关系、方式"），再举例说明。  
**正确做法：** 先展示大山的完整故事，让学习者形成直觉（"哦原来他不只是设了一个能力，还设了关系、还设了帮助方式"），然后框架作为"帮你把直觉变成结构"的工具出现。

**底层逻辑：** 框架是用来组织已有经验的，不是用来填充的。如果学习者没有相关经验，框架就变成了一张需要背诵的表格。

**在荻荻案例中的三个框架：**
1. **缺口地图**（能力缺口 + 情绪缺口 → 对应角色）— 在学习者自己分析了困境之后出现
2. **角色三层结构**（懂什么 + 为什么能靠近我 + 怎么帮我）— 在学习者看了大山的完整案例之后出现
3. **三种基础角色**（比你更懂 + 比你更稳 + 完全反对你）— 在学习者已经捏了一个角色、又理解了对立面角色之后出现

---

### 原则6：老师以"先行者"身份嵌入，不是"讲师"

**老师在学习系统中的角色定义：**
- 不是讲师（"我来教你"）
- 不是导游（"跟着我走"）
- 是先行者（"我走过这条路，在关键路口留了路标和笔记，但路是你自己走的"）

**先行者素材的特征：**
- 真实的情绪（"那个时候我整个人就贼慌"）
- 真实的犯错（"我最开始也没想到要加限制"）
- 真实的转变过程（"后来我发现小猴子开始软化，我才决定加锁"）

**为什么这种真实感很重要：** 因为AI可以生成任何"正确的建议"，但AI生成不了"一个真实的人在真实的困境中踩过的坑"。先行者素材是学习系统中AI无法替代的部分，也是老师的核心价值。

## 三、素材处理方法论：从原始分享到学习路径

### 第一步：识别"认知转变"

原始素材（分享录音、聊天记录、访谈等）中，信息层面的内容可以被AI秒总结。真正有学习价值的是**认知转变**——学习者需要经历的"从A到B的观念转变"。

**识别方法：** 在原始素材中找"转折点"——"我最开始以为……但后来发现……"的结构。每一个转折就是一个认知转变。

**在荻荻素材中识别出的5个认知转变：**
1. 从"AI帮我干活" → "AI是不同视角的协作者"
2. 从"我需要什么功能" → "我缺什么，角色从缺口生长"
3. 从"角色要厉害" → "关系设定决定你能不能开口"
4. 从"团队都是盟友" → "需要一个反对你的人，要主动设计信息隔离"
5. 从"角色的能力最重要" → "角色的自信度可以被设计来补你的不足"

### 第二步：确定认知转变的最佳排序

不是按照原始分享的顺序来排，而是按照**学习者的认知递进**来排。

**排序原则：**
- 从"跟学习者当前认知最近"的转变开始（降低门槛）
- "需要亲身体验才能理解"的转变放在实操之后
- "最反直觉"的转变放在学习者已经有了足够铺垫之后
- 最后一个转变应该是"能指向行动"的

### 第三步：为每个认知转变设计"经历路径"

每个认知转变需要回答四个问题：
1. **触发：** 学习者怎样才能"碰到"这个转变的必要性？（不能直接告诉他）
2. **素材：** 原始分享中哪些故事/案例可以在这个时机嵌入？
3. **做什么：** 学习者在这个环节需要做什么动作？（写、思考、操作、对比……）
4. **检验：** 怎么知道学习者到达了这个认知？（他的输出应该长什么样？）

### 第四步：确定"老师素材"的嵌入时机和方式

| 嵌入时机 | 嵌入目的 | 素材类型 |
|---------|---------|---------|
| 学习者刚暴露了自己的问题 | 共鸣："我不孤单" | 老师遇到的类似困境 |
| 学习者刚体验了局限 | 冲击："原来可以这样" | 老师的做法和结果 |
| 学习者刚完成了一个任务 | 深化："还可以更深" | 老师的进一步思考或迭代经验 |
| 学习者正在动手做 | **不嵌入** | — |
| 学习者完成整个路径 | 认同："原来我们是同路人" | 老师的总结性感悟 |

## 四、经验总结：这次设计过程中我学到的

### 1. 最难的不是设计模块，是决定"不讲什么"

荻荻一个小时的分享里有大量有趣的内容——弟弟的例子、医生的例子、奢侈品店的经验、跟不同行业的迁移……如果全部放进去，就变成了一个"信息堆叠"的课程。

学习系统设计的核心判断力是：**在所有"可以讲的"里面，识别出"必须经历的"，然后只围绕"必须经历的"来设计路径。** 其余的好内容可以作为延展素材，但不能占据主路径。

### 2. 模块之间的衔接比模块内容更重要

每个模块结束时，学习者的状态应该正好是"准备好进入下一个模块"的状态。比如：
- 模块二结束时，学习者应该感受到"多视角比单一回答更有价值" → 自然想知道"那我怎么创建不同视角"
- 模块四结束时，学习者应该体验到"角色总是支持我" → 自然准备好接受"需要对立面"

如果衔接不自然，说明某个模块的认知目标没有精确到位。

### 3. 实操环节的设计要留出"撞墙"的空间

模块四（动手捏角色）故意不给参照。这意味着有些学习者可能做得不好。但这恰恰是设计意图——**如果学习者捏出来的角色太泛、太像工具，他在模块五中就会更深刻地理解为什么需要对立面角色。**

学习系统不需要保证学习者每一步都做"对"。它需要保证的是：**不管学习者在动手环节做得如何，后续的反思环节都能让他从中获得认知。**

### 4. 原始素材中"不完美"的部分反而是最好的教学素材

荻荻讲话确实有点絮叨，但她说的"那个时候我整个人就贼慌"、"我就觉得这个事情肯定是稳了"（然后被竞品打脸）——这些"不完美"的表达恰恰是最真实的学习素材。

学习系统不需要把老师的表述"优化"成标准化的教学语言。**真实感是AI无法复现的价值，是学习系统中最不可替代的部分。**
