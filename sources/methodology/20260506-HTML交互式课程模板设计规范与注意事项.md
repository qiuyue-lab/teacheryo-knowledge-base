# HTML 交互式课程模板设计规范与注意事项

**撰写人：** TeacherYo  
**时间：** 2026-05-06  
**背景：** 基于荻荻"我和我的AI同事们"这一课的完整设计与实现过程，提炼出可复用的模板规范。供后续协作者在制作新课程时参考。

---

## 一、整体架构：两层结构

整个课程由两个 HTML 文件组成：

| 文件 | 职责 | 说明 |
|-----|------|------|
| `teacheryo-课程平台演示.html` | 外壳页面 | 个人主页 → 课程体系 → 课程详情，包含导航、回放链接、全屏按钮、底部模块导航栏 |
| `学习系统-XXX-v1.html` | 课程内容页 | 封面 + 6个学习模块的完整交互内容，通过 iframe 嵌入外壳页面 |

**核心原则：外壳负责导航和上下文，内容页负责学习体验。两者通过 `postMessage` 通信。**

---

## 二、外壳页面设计规范

### 2.1 页面路由

外壳页面是一个单页应用（SPA），用 JS 控制多个 `page` div 的显示/隐藏：

- **首页**（`pageHome`）：品牌介绍 + "立即体验"入口
- **课程体系**（`pageCourses`）：左侧导航栏 + 右侧课程卡片列表，支持标签分类切换
- **课程详情**（`pageDetail`）：顶部信息栏 + iframe 嵌入学习系统 + 底部模块导航

### 2.2 课程详情页要点

**顶部信息栏（detail-strip）：** 控制在一行以内。包含：
- ← 返回按钮
- 课程名称 + 分享人 + 标签 + 时长
- 回放链接（腾讯会议链接 + 提取码）
- 全屏学习按钮

**为什么不嵌入视频：** 视频托管和嵌入是很重的事情。直接放一个腾讯会议/飞书会议的回放链接 + 提取码，成本最低且够用。

**iframe 占满剩余视窗：** `height: calc(100vh - 60px)` + `flex:1`，让学习系统占据用户的主要视觉区域。

**底部模块导航栏：** 6个模块横排，序号圆点 + 模块名。当前模块高亮。点击可跳转。与 iframe 内容通过 postMessage 双向同步。

### 2.3 全屏学习模式

使用浏览器原生 Fullscreen API（`requestFullscreen`）。全屏时学习区域（含 iframe + 底部导航栏）占满整个屏幕，底部导航栏固定在屏幕底部。

## 三、课程内容页设计规范

### 3.1 封面页

**用户进入课程后首先看到的不是模块一的内容，而是封面页。** 封面页必须一屏可见（不需要滚动），包含：

- 课程标题和一句话简介
- 分享人信息
- **学习地图**：6个模块的名称以卡片形式排列（3×2 网格），让学习者一眼知道整个学习路径
- "开始学习"按钮
- 点击任意模块卡片也可以直接跳入该模块

**为什么需要封面页：**
1. 给学习者一个全局视角，知道自己要走的路
2. 避免 iframe 内嵌时"进来就要滚动"的割裂感
3. 降低心理门槛——看到地图再决定开始，比直接丢进内容更友好

### 3.2 模块结构

每个模块是一个 `<div class="module" id="m1">` ~ `<div class="module" id="m6">`，同一时间只有一个模块显示（`.active`）。

**每个模块的基本骨架：**

```
模块标题（section-divider）
  ↓
引导文 / 设问（prompt-box）
  ↓
学习者输入（textarea）
  ↓
提交按钮
  ↓
[隐藏内容] 老师素材 / 案例 / 框架（提交后展开）
  ↓
进入下一模块的按钮
```

**关键：内容分层显示。** 不是打开模块就看到全部内容，而是学习者完成一个动作后，下一段内容才展开（`.hidden` → 移除 hidden + 添加 `.fade-in`）。这样每一屏的信息量是可控的。

### 3.3 模块之间的导航

- 每个模块末尾有"进入下一模块"按钮，调用 `goTo(n)`
- 底部导航栏显示当前模块序号和标题（已被外壳页面替代，但独立打开时仍可用）
- 顶部有 4px 的进度条

### 3.4 与外壳页面的通信协议

学习系统通过 `postMessage` 与父页面通信：

**内容页 → 外壳页：**
- `{type: 'moduleChanged', current: 0~5, total: 6, title: '模块名'}` — 每次模块切换时发送
- `{type: 'showCover'}` — 回到封面时发送

**外壳页 → 内容页：**
- `{type: 'goToModule', index: 1~6}` — 底部导航栏点击时发送

## 四、内容设计注意事项

### 4.1 认知转变是设计单位，不是"知识点"

不要按照原始分享的叙述顺序来组织模块。要先从素材中提取"认知转变"（学习者需要从A观念转到B观念），然后按照**学习者的认知递进顺序**排列。

**具体操作：**
1. 听完/读完原始素材后，列出所有"我原来以为……后来发现……"的转折
2. 按照"离学习者当前认知最近 → 最反直觉"排序
3. 每个认知转变对应一个模块

### 4.2 老师素材的嵌入时机

| 时机 | 做什么 | 不做什么 |
|------|--------|---------|
| 学习者刚写完自己的困境 | 展示老师的类似困境 → 共鸣 | 不要在这里给建议 |
| 学习者体验了局限 | 展示老师的不同做法 → 冲击 | 不要提前剧透 |
| 学习者完成了一个任务 | 展示老师的进一步思考 → 深化 | 不要过早引入新概念 |
| 学习者正在动手做 | **什么都不给** | 不要给参照（会变成模仿） |

### 4.3 老师的口吻处理

保留老师的真实口吻和情绪表达。"那个时候我整个人就贼慌"比"当时心理压力比较大"更有效。不要把老师的话"规范化"成教材语言。

**但需要精简。** 原始分享通常很啰嗦，需要提炼核心段落。标准是：去掉这段话，学习者是否仍然能获得那个认知冲击？如果不受影响，就去掉。

### 4.4 互动环节的设计

- **每个模块至少一个输入点**（textarea），让学习者写点什么
- 输入内容不需要被系统"判断"，但应该被后续模块引用或呼应
- 按钮文案要口语化、有推动力（"写好了，继续" > "下一步"；"给我看点不一样的" > "提交"）
- 提交后展开的隐藏内容用 fade-in 动画，给出"因为你做了这个，所以现在看到这个"的因果感

### 4.5 控制每个模块的信息量

每个模块展开后的全部内容，理想状态是 2-3 屏滚动以内。如果超过了，说明这个模块承载了太多认知转变，需要拆分。

## 五、HTML / CSS / JS 技术注意事项

### 5.1 样式体系

当前使用的配色方案：

```css
--bg: #faf6f1;        /* 暖米色背景，区别于平台的冷白色 */
--accent: #e07a2f;    /* 橙色主色调 */
--green: #5a8a5e;     /* 绿色辅助（正向反馈） */
--pink: #c95c6a;      /* 粉色辅助（冲突/对抗） */
--blue: #4a7fa8;      /* 蓝色辅助（理性/框架） */
```

**外壳页面用蓝色系（与 TeacherYo 品牌一致），课程内容页用暖色系（与品牌形成区分，营造"学习空间"的氛围感）。**

### 5.2 卡片类型

| class 名 | 用途 | 视觉 |
|----------|------|------|
| `.card.accent` | 老师的核心故事 | 橙色左边框 |
| `.card.green` | 正向总结 / 阶段完成 | 绿色左边框 |
| `.card.pink` | 冲突 / 反思 / 警示 | 粉色左边框 |
| `.card.blue` | 框架 / 结构化知识 | 蓝色左边框 |
| `.quote-block` | 老师原话引用 | 带大引号装饰 |
| `.prompt-box` | 对学习者的提问 / 引导 | 虚线边框 |
| `.role-card` | 角色展示（头像 + 名称 + 发言） | 左侧圆形头像 |

### 5.3 隐藏/展开机制

```javascript
// 标准模式：点击按钮后展开隐藏内容
function showSomething(){
  document.getElementById('targetId').classList.remove('hidden');
  document.getElementById('targetId').classList.add('fade-in');
  document.getElementById('targetId').scrollIntoView({behavior:'smooth', block:'start'});
}
```

**所有"提交后才出现"的内容初始都加 `hidden` class。** 展开时移除 `hidden`、加 `fade-in` 动画、滚动到该区域。

### 5.4 模块切换机制

```javascript
function goTo(n){
  // n 是 1-based 模块序号
  const idx = n - 1;
  document.getElementById(modules[current]).classList.remove('active');
  current = idx;
  document.getElementById(modules[current]).classList.add('active');
  updateNav();
  window.scrollTo({top:0, behavior:'smooth'});
}
```

### 5.5 输入内容的处理

目前学习者的输入（textarea）仅在当前页面会话中有效，刷新即丢失。如果后续需要跨模块引用学习者输入，可以：
- 用 JS 变量存储（当前做法）
- 用 `localStorage` 持久化（刷新后恢复）
- 未来接入后端或 AI 接口

**XSS 防护：** 任何展示用户输入的地方，必须用 `esc()` 函数转义 HTML 特殊字符。

### 5.6 响应式适配

- 主内容区 `max-width: 720px` 居中
- 卡片网格（gap-row、lock-grid 等）在移动端降为单列
- 封面页学习地图在窄屏降为 2 列
- 外壳页面在移动端隐藏左侧 sidebar

### 5.7 文件命名规范

- 外壳页面：`teacheryo-课程平台演示.html`（全局唯一）
- 课程内容页：`学习系统-[课程名]-v[版本号].html`
- 两个文件必须放在同一目录下（iframe 用相对路径引用）

## 六、新增课程的操作清单

当需要为一个新的分享/老师制作交互式课程时，按以下步骤：

### Step 1：素材处理（内容层）

- [ ] 获取原始素材（分享录音转写 / 文档 / 聊天记录）
- [ ] 通读素材，提取所有"认知转变"（从A到B的观念变化）
- [ ] 按学习者认知递进顺序排列认知转变
- [ ] 为每个认知转变设计：触发 → 素材嵌入 → 学习者动作 → 进入下一个
- [ ] 提取老师的关键引用（保留真实口吻，精简长度）
- [ ] 输出：学习系统设计方案文档（参考 `20260506-荻荻素材-学习系统设计方案v1.md`）

### Step 2：HTML 制作（技术层）

- [ ] 复制 `学习系统-我和我的AI同事们-v1.html` 作为模板
- [ ] 修改封面页内容（标题、简介、分享人、模块名称）
- [ ] 逐模块替换内容（保持骨架结构不变）
- [ ] 调整隐藏/展开的 JS 函数名和目标 ID
- [ ] 确保每个模块的 textarea 有独立 ID
- [ ] 确保 postMessage 通信正常

### Step 3：外壳页面接入

- [ ] 在外壳页面的"通用场景课程"或"教育场景课程"中添加新的课程卡片
- [ ] 新建课程详情页（或复用 `pageDetail` 的结构，如果只有一个课程的话）
- [ ] 更新 iframe 的 src 为新课程文件名
- [ ] 更新底部模块导航栏的模块名称
- [ ] 更新顶部信息栏的课程名、分享人、回放链接和提取码

### Step 4：检查

- [ ] 封面页是否一屏可见（不需要滚动）
- [ ] 每个模块的隐藏内容是否正确展开
- [ ] 底部模块导航栏是否与 iframe 内容同步
- [ ] 全屏模式是否正常
- [ ] 移动端是否可用

## 七、已知待优化项

1. **多课程支持：** 目前外壳页面的课程详情页是硬编码的，如果有多门课程需要改为动态渲染
2. **学习进度持久化：** 目前刷新后进度丢失，后续可用 localStorage 保存
3. **学习者输入跨模块引用：** 模块一写的困境应该在后续模块中被引用展示，目前还未实现
4. **AI 对话接入：** 未来可以在特定节点接入 AI agent，让学习者和"老师分身"对话
5. **课程内容的精细打磨：** 当前 v1 版本的文案和交互流程需要逐模块打磨
