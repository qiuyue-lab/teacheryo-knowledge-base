# 桌宠「小咕噜」：用好奇心驱动幼儿项目化学习

> **分享人**：俞坚（想法源起，幼教背景）× 希希（技术实现与现场演示）
> **时间**：2026年4月17日 黑客松后续系列分享·第二组
> **主题**：把"抓不住的好奇心"做成一只会听会答的桌面小宠，帮幼师捕捉孩子的真实兴趣，驱动 PBL 课程主题审议

---

## 一、项目缘起：小朋友的好奇心，怎么才能不被漏掉？

### 一个评委指出的"偏题"
俞坚老师开场先坦诚地回应：桌宠小组虽然在黑客松里很受欢迎，但评委也提醒——项目对情境卡出题方向稍有偏离。恰好呼应了 Lasso 老师前面讲的那句话：**"你的天花板就是你的目标"**。用 AI 赋能教学时，千万不要本末倒置，沉迷在造锤子的过程里，忘了最初要创造的价值。

### 真正的出发点：捕捉兴趣 → 激发探究
团队的初心是：**怎么激发学生的好奇心？** 希希老师提出她长期想做的"捉宠"形态，两条线一拍即合。

### 为什么好奇心对幼儿那么关键
俞坚老师有丰富的幼教经验。她强调幼儿的学习机制和中小学、大学完全不同：
- **亲身体验 + 实际操作 + 好奇心驱动**，这是幼儿获取经验的主要方式
- 兴趣点一旦没抓住，**一分钟内就会走神**
- 这对幼儿园"项目化学习（PBL）"尤其致命——PBL 的第一步就是**主题审议**，而主题审议必须基于老师对孩子日常好奇心的捕捉

所以小咕噜要解决的真问题是：**帮老师抓住那些转瞬即逝、但又特别宝贵的"小朋友的疑问"**。

## 二、小咕噜的两个关键设计

### 设计 1：不直接给答案，用苏格拉底式提问回抛
直接告诉答案，对幼儿的学习反而有害。小咕噜的对话机制是：
> 小朋友提问 → 小咕噜及时反馈 → 再抛回一个更深的问题 → 驱动孩子继续探究

### 设计 2：形象可爱到能让小朋友愿意聊
名字也斟酌了很久。本来想叫"小小好奇"或"小号老师"，但觉得不够可爱。最后问了 Claude Code，**"咕噜"**胜出——
- 拟声词，可爱
- 隐含"转动 / 滚动"的意向，对应"思维不断转动探索"

### 未来规划
把这只桌宠和其他工具联动：
- 用 **Open Claude + Skill** 调用 **NotebookLM** 的文生图
- 把一周里孩子们最好奇的问题**可视化成手抄报**展现给全班
- 以此**驱动下一阶段课程**走向

## 三、希希的两句"过来人建议"

### 1. 自己想的，比 AI 想的更有趣
> 自己的想法里带着自己的喜好和审美，落地的过程才会好玩。
> 全程交给 AI 就没那么有趣了。

### 2. 前期准备越充分，落地越快
> 直接把方案扔给 AI，它确实能很快给结果，但往往是你不满意的。
> 后面再改，坑越来越大。

## 四、小咕噜的落地思路：先想清楚，再动手

### Step 1：场景先捋清
- **使用场景**：小朋友没手机 → 装在教室电脑上（能配班班通白板展示更好）
- **交互方式**：语音输入？直接语音输出还是文字？一轮对话就结束吗？
- **数据归档**：孩子的提问是保存在本地 Excel、飞书文档，还是云端数据库？老师如何及时看到？

### Step 2：技术选型
- 输入：语音转文字
- 编程语言：自己会的优先（比如 Python）；不会的，让 AI 给最简单的实现路径
- 数据处理：本地 Excel / 飞书文档 / 云数据库三选一

### Step 3：15 分钟对齐，再动手
黑客松现场时间紧，他们先用 15 分钟把上面的方案讨论透并沉淀成文档，再分工开发——这是"防跑偏"的关键。

## 五、希希的 AI 开发"找资料 3 条技巧"

### 技巧 1：用约束条件去问 AI
直接问"我要做一个桌宠" → AI 给一大堆参考资料
用约束条件去问 → 告诉 AI "我只会 python" "我要做网页/App/小桌宠" "我熟悉的工具是 Cursor/豆包" → AI 的推荐会精准匹配

### 技巧 2：评估开源项目要不要借鉴
- 借鉴其中一个功能模块？
- 只做微调？
- 对不上就别硬搬，否则改起来 bug 越来越多
- **像桌宠这种小项目，更推荐直接让 AI 自己写**

### 技巧 3：bug 的来源，未必是代码
初学者最大的误区——"出 bug 就是代码错了"。其实：
1. **更多情况是你没讲清楚**（AI 的理解和你不一样，去看它的思考过程，找到误会点）
2. **信息不全**（有些模型官网有特殊调用规则，要把开发者文档示例喂给 AI）
3. **电脑本身配置问题**（希希的调试技巧：换一个 AI，专门让它"先不看代码，帮我梳理项目要哪些电脑配置"）
只有极少数情况真的是代码出错。

## 六、现场演示：小咕噜的"从 0 到 1"

希希老师给现场老师们的定心丸：**这件事非常简单**——
> 你只要有想法，现在的 AI 工具都能实现。

### 第一步：让图片像浮窗一样动起来

**工具准备**：
- 下载 Python（官网直接下，需要激活码可以在闲鱼花两块钱买）
- 安装 Cursor（闲鱼五块钱左右可以买到带 Pro 会员的账号）

**操作**：
1. 桌面建一个文件夹
2. 上网找一张动图 → 小程序抠图（背景透明）→ 放进文件夹
3. Cursor 打开这个文件夹
4. 一句话告诉 AI：
   > 我有一张动图，想让它变成浮窗效果做一个桌宠。帮我装一下对应的 Python 库，一键实现多层浮窗效果。
5. AI 写出一段 Python 代码，点击运行 → 桌宠视觉效果就有了

**核心知识**：Python 有处理图片的库可以实现浮窗，这一个关键信息足以开局。

### 第二步：让桌宠能说话（接大模型）

调大语言模型需要三样东西：
1. 模型显示名字
2. 英文模型名（API 标识）
3. API Key（密钥 / URL）

**如果是用本地大模型**，不需要 API Key——推荐 **Ollama**：
1. Ollama 官网下载安装
2. 终端运行 `ollama`
3. 用 `ollama pull 模型名` 下载轻量模型（适合本地部署）
4. 得到一个本地 URL → 把这个 URL 给 AI → 告诉它"我用 Ollama 调用 XX 模型" → AI 会自动生成代码
5. 让桌宠"右键打开菜单，点击就能对话" → AI 直接帮你把交互写好
6. Python 点运行 → 上线调试

现场演示因为文件夹太多略微卡顿，但整体思路完整跑通。

### 第三步：遇到 bug 就回到前面那 3 条技巧
1. 先排查"我是不是没讲清楚"
2. 再排查"信息是不是给全了（文档示例）"
3. 最后才去换 AI 排查电脑配置问题

## 七、这次分享里最值得带走的底层认知

1. **目标感不能丢**：做 AI 应用容易变成"沉迷造锤子"，要时刻回到"你要解决的教育问题是什么"
2. **幼教 × AI 的发力点不是答案，是反问**：苏格拉底式提问才是幼儿学习的正确打开方式
3. **好 AI 应用 = 精准场景 + 明确交互 + 数据归档链路**，这三件事必须在动手前敲定
4. **Python + Cursor + Ollama** 是老师做小应用最亲民的三件套
5. **85% 的 AI bug 其实是沟通问题**，改变提问方式比改代码更快
6. **约束条件**是让 AI 推荐精准的杀手锏——"我只会 X，我要做 Y"

> "小朋友在思维里不断转动探索" —— 小咕噜的名字意象，也是这个项目真正想交付给课堂的东西。
