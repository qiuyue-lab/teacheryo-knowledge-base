# 造神方法论：AI角色系统的构建与迭代

> 来源：伏羲标注引擎迭代过程中的实践提炼
> 定位：所有角色之上的元方法论，指导角色的设计、检验与改进
> 日期：2026-02-20

---

## 核心认知

角色系统和角色标注的知识一样，都是从实践中长出来的。不存在一次设计到位的角色，只存在不断从实践中发现问题、修复问题的迭代过程。

造神者和神遵循同一条归纳路径：

```
神标注题目：  观察具体题目 → 发现框架装不下 → 如实记录 → 积累验证 → 长成知识
造神者造神：  观察具体执行 → 发现指令管不住 → 定位原因 → 修复验证 → 长成方法论
```

---

## 五条造神法则

### 法则1：原则不嵌入动线，等于没写

AI的注意力权重天然偏向execution层的程序性指令，thought层的声明性原则会被"知道但做不到"。

**检验方法**：对角色中的每一条原则，问——它在执行流程中有没有对应的强制前置步骤？

- 有 → 原则能落地
- 没有 → 原则只是标语，必然被忽视

**操作**：把原则转化为执行流程中的"⚠️强制检查点"，放在对应动作之前，而不是写在thought里期望AI自觉遵守。

---

### 法则2：格式即约束，约束即深度

允许表格，AI就压缩推理过程。要求逐句展开，AI就不得不把判断理由写出来。

**检验方法**：对每个输出格式要求，问——这个格式有没有给AI留下"合规地偷工减料"的空间？

- 有 → 换格式，堵住压缩空间
- 没有 → 格式合格

**核心认识**：输出格式不是排版偏好，是思维质量的物理限制。设计执行流程时，格式要当作认知深度的控制手段来设计。

---

### 法则3：指令精度决定执行质量

"逐句分析"和"逐句展开，禁止用表格压缩"——意思接近，执行结果天差地别。前者给了AI偷懒空间，后者堵死了。

**检验方法**：对每条执行指令，问——这句话有没有给AI留下"合规地偷工减料"的解读空间？

**操作原则**：
- 用"禁止X"代替"尽量Y"
- 用具体格式模板代替抽象描述
- 用"必须先做A再做B"代替"注意A和B"
- 模糊的指令 = 不存在的指令

---

### 法则4：每次修复暴露下一层问题

这不是设计失败，是角色系统的正常生长方式。

**实际案例**：
- 第一轮：发现伏羲分析浅 → 加了5个强制检查点
- 第二轮：实践标注 → 发现四元分析被压缩成表格
- 第三轮：改输出格式约束 → 下一轮实践会暴露新问题

**造神者心态**：不追求一次到位，追求每次迭代都修复一个真实问题。角色系统的成熟度 = 经历过的实践-修复循环次数。

---

### 法则5：不跑真题，不算改完

改完执行流程后，必须立刻用一个真实场景跑一遍，对照输出检查。

**检验方法**：
- 改完 → 跑真题 → 对照输出逐项检查 → 发现新问题 → 继续改
- 改完 → 觉得"应该没问题了" → ❌ 必然有遗漏

**核心认识**：人眼对比两份输出（改前vs改后）是发现问题最有效的方式。抽象地审查流程文件几乎不可能发现执行层面的漏洞。

---

## 三层分离原则

造神过程中产生的认知分属三个不同层面，不可混淆：

| 层面 | 内容 | 归属 | 举例 |
|------|------|------|------|
| 造神者方法论 | 如何设计、检验、改进角色 | 本文档 | "原则必须嵌入动线" |
| 角色执行系统 | 角色的thought + execution + knowledge | 角色文件 | 伏羲的五阶段标注流程 |
| 领域知识数据 | 具体学科的编码、案例、模式 | 插件文件 | 历史学科编码表 |

**检验标准**：
- 造神方法论里不该出现具体编码（如"1.3.3"）
- 角色执行系统里不该出现"如何设计角色"的内容
- 领域知识数据里不该出现流程步骤

---

## 造神者的自检清单

每次修改角色后，逐项检查：

```
□ 新增的原则是否都有对应的执行动作？
□ 输出格式是否堵死了压缩推理的空间？
□ 执行指令是否足够精确，没有模糊解读空间？
□ 是否用真实场景跑过一遍并对照检查？
□ 发现的新问题是否已记录待修？
□ 修改是否在正确的层面？（造神方法论 vs 角色系统 vs 领域数据）
```
