# 能力点标注专家系统蒸馏：元认知工作方法论

> 来源：ability-point-coach 角色系统（21个模块）
> 蒸馏目标：提取普适性的元认知规则和工作方法，脱离具体编码体系
> 日期：2026-02-20

---

## 一、核心认知立场：归纳优先于演绎

整个系统的底层认知立场只有一句话：**先看事实，再判断分类**。

这不是口号，而是贯穿所有模块的操作原则：

- 标注能力点时：先读官方解析原文，再查编码表匹配——不是先想"这题应该考什么"再找证据
- 识别命题技术时：先观察干扰项的实际特征，再验证是否符合已有分类——不是看到"时空错位"就直接贴标签
- 发现新规律时：先积累≥3个相似案例，再归纳为模式——不是单题就下结论
- 扩展知识库时：先多省验证，再正式纳入——不是单省发现就扩充

**反面教材（演绎思维的陷阱）**：
```
看到选项时空错位 → 直接标注QT02        ❌ 演绎
看到"分析综合" → 直接匹配"概括"编码    ❌ 削足适履
```

**正确路径（归纳思维）**：
```
观察实证特征 → 提取核心特征 → 验证是否符合已有分类 → 判断编码
```

## 二、两个不可混淆的编码层面

系统中存在两类性质完全不同的编码，混淆它们是最常见的认知错误：

### 层面1：规定性编码（能力点/微题点）
- 来源：课程标准
- 性质：**规定性的**——编码表里有什么就只能用什么，不能自创
- 回答的问题：**这道题考了什么能力？**
- 演化方式：发现缺失→多省验证→正式扩充→版本递增

### 层面2：描述性编码（堵点模式BP/命题技术QT/错误类型E/思维模型M）
- 来源：从具体题目分析中归纳出来的实证知识
- 性质：**描述性的**——从题目中分析出什么就记录什么，本身不断演化
- 回答的问题：**学生卡在哪里？命题人怎么设陷阱？**
- 演化方式：单题发现→标记待验证→≥3题确认→纳入知识库

**关键区别**：
- 层面1的编码错了（如把1.2.1的定义搞错），整个标注结果不可用
- 层面2的编码是开放的，发现新模式就提出新编码，这是正常的知识演化

## 三、四个核心元认知规则

### 规则1：四元区分法——区分"做什么"和"怎么做"

官方解析中的每个表述，必须先判断它属于哪一类：

| 类型 | 含义 | 是否独立能力点 | 识别信号 |
|-----|------|--------------|---------|
| WHAT | 做什么（独立能力要求） | ✅ 是 | 动词+宾语（"获取信息""建立联系"） |
| HOW | 怎么做（方法要求） | ❌ 否，融入WHAT | "在...基础上""通过...""运用...方法" |
| WITH WHAT | 用什么（知识/工具支撑） | ❌ 否，融入WHAT | "结合所学知识""运用...理论" |
| TO WHAT EXTENT | 到什么程度（程度要求） | ❌ 否，融入WHAT | "正确""全面""深刻""有效" |

**操作规则**：只有WHAT是独立能力点，其余三类融入对应的WHAT。

**防错信号**：能力点数量≥7个时，大概率存在过度拆分——检查是否把HOW/WITH WHAT/TO WHAT EXTENT误判为独立能力点。

### 规则2：三条件验证法——防止贴标签

对任何分类判断（命题技术、堵点模式、错误类型），都必须验证三个条件：

| 条件 | 验证内容 | 判断标准 |
|------|---------|---------|
| 条件1 | 本质是否一致？ | 核心机制相同 |
| 条件2 | 方法/表现是否一致？ | 外在特征相似 |
| 条件3 | 有实证案例支撑吗？ | 有具体题目佐证 |

**判断规则**：
- 三条件全✅ → 匹配度≥90% → 确认使用
- 至少一个❌ → 匹配度<70% → 不使用
- 所有已有分类都<70% → **红线触发** → 必须提出新分类

**红线机制的意义**：宁可暂时"未分类"，也不要"错误分类"。削足适履会污染知识库，错误归类会误导后续所有标注。

### 规则3：干扰项的断点映射——从错误反推能力缺失

每个干扰项不是随意设置的，它对应学生思维链条上的一个具体断点：

```
干扰项 → 学生在哪一步卡住了 → 缺失哪个能力点 → 认知深度是什么层级
```

**操作流程**：
1. 对每个干扰项，判断：知识点本身是否正确？在本题情境下逻辑是否成立？
2. 根据判断结果分类错误类型（知识错误/逻辑错误/理解错误）
3. 将每个干扰项映射到思维链条的具体断点位置（步骤X→步骤Y）
4. 按断点位置排序：越靠后=认知越深=越难突破

**教学价值**：
- 选C的学生→卡在步骤2（浅层）→需要补基础
- 选B的学生→卡在步骤4（中层）→需要补关联能力
- 选A的学生→卡在步骤6（深层）→需要补深层思维

这直接告诉教师：不同错误选项的学生，需要不同的教学干预策略。

### 规则4：实事求是的唯一标准——官方解析的客观语义

标注的唯一依据是**官方解析的客观语义和结构**，不是：
- ❌ 数据库有什么就匹配什么
- ❌ 经验值是什么就标成什么
- ❌ 任何外在的预设标准或统计阈值

**防错信号**：当你发现自己在"解释为什么能匹配"时，已经在削足适履了。正确的匹配应该是直接对应，不需要解释。

## 四、知识演化的螺旋机制

系统最深层的方法论不是某个具体规则，而是一套**知识如何从具体题目中生长出来**的机制：

### 第一圈：从题目到发现

```
具体题目 → 标注时遇到困难（找不到匹配/匹配不精确）
         → 如实记录困难（不强行归类）
         → 标记为"待验证"
```

### 第二圈：从发现到假设

```
多道题出现相似困难 → 提取共同特征
                   → 提出假设（新能力点/新堵点模式/新命题技术）
                   → 用三条件验证法检验
```

### 第三圈：从假设到规律

```
单省≥3题验证 → 初步确认（⭐⭐⭐）
多省验证     → 稳定确认（⭐⭐⭐⭐）
高频+多省    → 高度确认（⭐⭐⭐⭐⭐）→ 正式纳入知识库
```

### 第四圈：从规律到指导

```
已确认的规律 → 指导新题标注（但不是机械套用）
新题标注     → 可能验证规律，也可能发现规律的边界
发现边界     → 修正规律 → 回到第一圈
```

**关键约束**：
- 每一圈都必须有实证数据支撑，不能主观臆断
- 单题发现只做标记，不立即扩展知识库
- 规律验证率<50%持续3套试卷 → 修正规律表述
- 观测题点总数≤6个，超过时需审视编码体系本身

## 五、方法论与数据的分离原则

这是系统设计中最精妙的一点：**方法永恒，数据动态**。

| 层面 | 内容 | 存放位置 | 演化方式 |
|------|------|---------|---------|
| 方法论 | 如何识别、如何验证、如何归纳 | thought文件 | 发现新的识别原理时更新 |
| 执行流程 | 具体操作步骤、模板、检查清单 | execution文件 | 发现流程缺陷时更新 |
| 知识数据 | 具体的编码列表、频率统计、案例 | knowledge文件/数据库 | 每次标注后可能更新 |

**检验标准**：如果方法论文件中出现了"QT02出现频率26.7%"这样的具体数据，就违反了分离原则。方法论应该写"如何识别命题技术"，而不是"某个技术出现了多少次"。

这个分离的意义在于：
- 方法论可以迁移到其他学科（物理、政治等），只需替换知识数据
- 数据可以不断更新，不影响方法论的稳定性
- 新人学习时，先学方法论（少量），再熟悉数据（大量）

## 六、三层分析框架——从学生到命题人到元认知

这是堵点分析的核心架构，也是整个系统深度分析能力的来源：

```
第一层：学生视角（堵点模式）
  学生的思维在哪里卡住？为什么卡住？
  → 输出：堵点位置、学生行为分析（能做什么/不能做什么）

第二层：命题人视角（命题技术）
  命题人如何设计陷阱？为什么有效？
  → 输出：干扰项设计逻辑、技术组合分析

第三层：元认知视角（本质规律）
  背后的普遍规律是什么？如何复用？
  → 输出：跨题验证的规律、教学启示
```

三层不是并列的，而是递进的：
- 第一层回答"是什么"
- 第二层回答"为什么"
- 第三层回答"意味着什么"

只做第一层=浅层标注（伏羲当前水平）
做到第三层=深度分析（能力点教练的目标水平）

## 七、蒸馏结论

从21个模块中提取出来的，不是一套复杂的框架，而是6个可迁移的认知原则：

1. **归纳优先于演绎**：先看事实再判断分类，不是先有分类再找证据
2. **区分规定性编码和描述性编码**：前者不能自创，后者鼓励演化
3. **四元区分法**：区分WHAT/HOW/WITH WHAT/TO WHAT EXTENT，只有WHAT是独立能力点
4. **三条件验证+红线机制**：防止贴标签和削足适履
5. **干扰项断点映射**：从错误反推能力缺失，按认知深度排序
6. **知识螺旋演化**：题目→发现→假设→验证→规律→指导→新题目

这6条原则脱离了具体的BP/QT编码、具体的历史学科知识、具体的数据库表结构。它们是**关于"如何从具体题目中归纳出规律"的方法论**，可以迁移到任何需要从实践中提炼认知规则的场景。

BP/QT库不是预设的框架，而是这套方法论运行后的产出物。方法论是因，知识库是果。
