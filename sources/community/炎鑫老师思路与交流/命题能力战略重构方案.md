# 命题能力战略重构方案 v2.0

**创建日期**: 2025-01-08
**方案版本**: v2.0 (基于姜子牙战略分析)
**核心洞察**: 解析与命题是同一认知能力的双向应用
**战略定位**: 不建独立角色，给Analyst增加"命题设计模式"

---

## 一、核心洞察：解析↔命题的认知对称性

### 1.1 哲学层面：认识论的可逆性

```
分析题目 ←→ 设计题目
（解构）      （建构）

都需要理解同一个本质：
"如何通过题目考查知识点"
```

**认知的对称性**：
- 能深刻理解"为什么这道题这样设计" → 就能"设计出同样水平的题"
- 能准确识别"这道题考查什么、如何考查" → 就掌握了"命题的底层逻辑"

### 1.2 Analyst的隐性命题能力

**现有能力分析**：

| Analyst已有能力 | 正向应用（解析） | 反向应用（命题） |
|----------------|-----------------|-----------------|
| question-deconstruction | 解构题目结构 | 设计题目结构 |
| answer-structure-analysis | 分析给分点 | 设计评分标准 |
| knowledge-retrieval-thinking | 检索相关知识 | 选择命题材料 |
| verifiability-thinking | 验证解析准确性 | 确保命题可验证性 |

**工作流程的可逆性**：

```
Analyst 正向（解析）：
真题 → 解构 → 识别考查逻辑 → 生成评分标准

Analyst 反向（命题）：
考查目标 → 选择材料 → 设计设问 → 设计干扰项 → 生成评分标准
```

---

## 二、战略决策：增加模式 vs 新建角色

### 2.1 方案对比

| 维度 | 方案A: 独立命题专家 | 方案B: Analyst第4模式 ⭐ |
|------|-------------------|------------------------|
| **开发周期** | 6-8周 | 2-3周 |
| **知识库建设** | 需建真题库（200-300题） | 复用5本教材知识库 |
| **思维模式** | 新建2-3个 | 复用现有+新增2个 |
| **能力复用** | 需重新定义 | 100%复用Analyst能力 |
| **质量验证** | 需要Analyst分析 | 内置自我验证闭环 |
| **省份风格** | 需建风格库 | 用记忆系统沉淀 |
| **投资回报** | 高投入，收益不确定 | 低投入，增量价值 |

### 2.2 战略选择：方案B ⭐

**核心优势**：

1. **降维打击**
   - 别人需要"解析专家"+"命题专家"两个系统
   - 我们只需要一个Analyst，双向能力

2. **自我强化闭环**
   ```
   解析真题 → 理解命题逻辑 → 命题能力提升
       ↓                              ↓
     积累经验                    生成新题
       ↓                              ↓
     记忆沉淀  ←  自我分析质量  ←  验证迭代
   ```

3. **最小投入，最大产出**
   - 2-3周 vs 6-8周
   - 复用 vs 新建
   - 自然积累 vs 人工构建

## 三、技术实现方案

### 3.1 Analyst新增第4工作模式

#### 现有三模式：
1. 选择题解析模式
2. 主观题解析模式
3. 评分辅助模式

#### 新增第4模式：命题设计模式 ⭐

```yaml
工作模式4: 命题设计模式

输入:
  - 知识点范围 (如"洋务运动")
  - 题型 (选择题/主观题)
  - 考查目标 (知识记忆/理解/应用/分析)
  - 难度要求 (基础/中等/较难)
  - 可选: 参考真题ID (学习其风格)

核心流程:
  Step 1: 知识本质分析
    - 调用 knowledge-retrieval-thinking
    - 从5本教材提取相关知识
    - 识别核心概念和常见误区

  Step 2: 考查逻辑设计
    - 运用 question-deconstruction (逆向应用)
    - 设计考查的切入点
    - 确定材料选择方向

  Step 3: 题目结构设计
    - 选择材料 (从知识库或给定)
    - 设计设问
    - 设计干扰项逻辑 (如果是选择题)

  Step 4: 评分标准设计
    - 运用 answer-structure-analysis
    - 生成给分点结构
    - 生成JSON评分细则

  Step 5: 自我验证 ⭐
    - 切换回"解析模式"
    - 分析自己命制的题目
    - 检查考查逻辑是否成立
    - 如不通过，重新设计（迭代最多3轮）

输出:
  - 完整题目（材料+设问+选项）
  - 标准答案
  - 评分细则(JSON格式)
  - 命题设计说明 (考查意图、干扰项逻辑)
  - 自我验证报告
```

### 3.2 新增思维模式文件

#### 文件1: `thought/question-design-thinking.thought.md`

**核心内容**：
- 如何从考查目标倒推题目设计
- 如何选择合适的材料类型
- 如何设计有效的干扰项（4种类型）
- 如何控制难度

**知识点本质理解框架**：
```
知识点分析维度：
1. 核心概念是什么？
2. 学生常见误区是什么？
3. 与其他知识点的易混淆点在哪？
4. 可以从哪些角度切入考查？
```

**干扰项设计思维**（从Analyst解析中提炼）：
```
干扰项四大类型：
1. 时间错位型
   - 原理：混淆时间先后顺序
   - 设计：选择时间接近但不符的史实
   - 示例：德川幕府（17世纪）vs 题干（15-16世纪）

2. 概念混淆型
   - 原理：张冠李戴相似概念
   - 设计：选择同领域但不同的制度/政策
   - 示例：郡县制 vs 分封制

3. 逻辑冲突型
   - 原理：方向相反或矛盾
   - 设计：与材料主旨相反的结论
   - 示例：集权强化 vs 分权改革

4. 超范围型
   - 原理：正确但材料未涉及
   - 设计：相关但不是题目考查点的内容
   - 示例：政治制度题中放经济政策选项
```

#### 文件2: `thought/knowledge-essence-thinking.thought.md`

**核心内容**：
- 如何理解知识点的本质而非表面
- 如何识别学生认知误区
- 如何设计考查的层次（记忆→理解→应用→分析）

**知识本质分析框架**：
```
三层理解模型：

表层（What）：
- 时间、地点、人物、事件

中层（How）：
- 过程、原因、影响

深层（Why）：
- 本质矛盾、历史规律、时代特征

命题原则：
- 基础题考表层
- 中等题考中层
- 较难题考深层
```

### 3.3 新增工作流程文件

#### 文件: `execution/question-design-workflow.execution.md`

**完整工作流**：

```markdown
# 命题设计工作流

## 阶段1: 需求理解（2分钟）

### 输入解析
- 知识点范围确认
- 题型确定
- 考查目标明确
- 难度要求理解

### 知识库检索
- 调用 knowledge-retrieval-thinking
- 检索相关教材内容（top_k=5）
- 提取核心知识点
- 识别常见误区

## 阶段2: 考查逻辑设计（5分钟）

### IF 是选择题 THEN
  - 确定正确选项的考查角度
  - 设计3个干扰项的类型
  - 每个干扰项对应一种误区

### IF 是主观题 THEN
  - 确定设问的层次（分析/评价/比较）
  - 设计给分点结构
  - 规划答案的逻辑框架

## 阶段3: 材料选择与设计（10分钟）

### 材料来源优先级
1. 从教材知识库提取
2. 基于教材内容改编
3. 历史文献摘录（需标注来源）

### 材料要求
- 真实性：不虚构史料
- 适配性：与考查目标匹配
- 难度控制：字数和复杂度适中

### 材料字数标准
- 选择题：100-200字
- 主观题：300-800字（1-3则材料）

## 阶段4: 设问与选项设计（10分钟）

### 选择题设计
**正确选项**：
- 明确对应考查目标
- 基于材料可推出
- 表述准确无歧义

**干扰项设计**（逐个设计）：
```
干扰项A：[类型] + [具体内容] + [为什么能干扰]
干扰项B：[类型] + [具体内容] + [为什么能干扰]
干扰项C：[类型] + [具体内容] + [为什么能干扰]
```

### 主观题设问
**设问公式**：
- 材料解读型："根据材料，概括/归纳/提取..."
- 知识调用型："结合所学，说明/分析/阐述..."
- 综合型："根据材料并结合所学，评价/论证..."

**分值分配**：
- 明确每问分值
- 每2-3分对应1个给分点
- 总分值：8-15分

## 阶段5: 评分标准生成（8分钟）

### 选择题
- 正确答案：X项
- 简要说明：为什么选X，为什么排除其他

### 主观题
**生成JSON格式评分细则**：
```json
{
  "scoring_strategy": "逐点计分/任答N项/两层次评价",
  "total_score": 12,
  "score_points": [
    {
      "point_id": 1,
      "content": "给分点内容",
      "score": 3,
      "keywords": ["核心要素1", "核心要素2"]
    }
  ]
}
```

## 阶段6: 自我验证（5分钟）⭐

### 切换到解析模式
- 将生成的题目作为输入
- 运行选择题解析/主观题解析流程
- 生成解析报告

### 质量检查清单
- [ ] 考查目标是否明确？
- [ ] 材料是否真实可靠？
- [ ] 设问是否清晰无歧义？
- [ ] 干扰项是否有效（选择题）？
- [ ] 评分标准是否科学？
- [ ] 难度是否符合要求？

### 验证结果判定
**IF 通过率 ≥ 5/6 THEN**
  → 输出最终题目

**IF 通过率 < 5/6 THEN**
  → 分析问题点
  → 迭代优化（最多3轮）
  → 如仍不通过，标注"需人工审核"

## 阶段7: 输出交付（2分钟）

### 标准输出包
1. **题目文件**（Markdown格式）
   - 题目内容（材料+设问+选项）
   - 标准答案
   - 评分细则（JSON）

2. **设计说明**
   - 考查目标
   - 命题思路
   - 干扰项逻辑（选择题）
   - 难度控制说明

3. **自我验证报告**
   - 质量检查结果
   - 改进建议（如有）

### 用户提示
⚠️ **本题由AI生成，建议人工审核后使用**
- 已通过自我验证（X/6项）
- 建议重点检查：[具体项]
```

## 五、质量保证机制

### 5.1 自我验证闭环 ⭐

**核心优势**：Analyst既是命题者，又是审核者

```
命题模式 → 生成题目
    ↓
解析模式 → 分析题目
    ↓
质量评估 → 6项检查
    ↓
IF 通过 → 输出
IF 不通过 → 重新设计（最多3轮）
```

**6项质量检查**：
1. 考查目标是否明确？
2. 材料是否真实可靠？
3. 设问是否清晰无歧义？
4. 干扰项是否有效（选择题）？
5. 评分标准是否科学？
6. 难度是否符合要求？

### 5.2 分级质量标准

**不追求完美，分级管理预期**

| 质量等级 | 通过率 | 定位 | 使用场景 |
|---------|--------|------|----------|
| A级（优秀） | ≥90% | 接近真题水平 | 正式考试、高质量练习 |
| B级（良好） | 70-90% | 日常教学可用 | 课堂练习、作业 |
| C级（及格） | 50-70% | 需人工优化 | 初稿素材 |
| D级（不及格） | <50% | 不建议使用 | 废弃或大改 |

**MVP目标**：达到B级（70%）

### 5.3 人工审核建议

**强制审核场景**：
- 用于正式考试的题目
- 高风险应用（如模拟高考）
- 自我验证未通过的题目

**可选审核场景**：
- 日常课堂练习
- 学生自测题

**审核重点**：
1. 知识准确性（时间、人名、事件）
2. 干扰项有效性（是否太简单）
3. 材料真实性（是否虚构史料）
4. 政治正确性（历史观念）

## 六、风险管理

### 6.1 主要风险点

#### 风险1：命题质量不如解析质量 ⚠️

**原因**：
- 解析是收敛任务（分析给定题目）
- 命题是发散任务（从无到有创造）
- 创造难度 > 分析难度

**应对**：
1. **降低预期**：目标是70分水平，不是95分
2. **自我验证**：命题后立即自我分析
3. **分级使用**：明确适用场景（日常练习 vs 正式考试）
4. **人工审核**：建议使用前审核

**退化方案**：
- 如果从零设计质量不够
- 退化到"参照改编模式"
- 保持真题结构，替换内容

#### 风险2：干扰项设计流于表面 ⚠️

**问题**：
- 真题干扰项基于深刻的学生认知误区理解
- AI可能只做简单的时间错位、概念替换

**应对**：
1. **从真题学习**：
   - 分析100道真题的干扰项
   - 提取常见模式库
   - 命题时应用

2. **明确标注类型**：
   ```
   选项A：[时间错位型] 德川幕府17世纪 vs 题干15-16世纪
   选项B：[概念混淆型] 郡县制 vs 分封制
   ```

3. **质量分级**：
   - 高级干扰项：基于认知误区
   - 中级干扰项：时间、概念混淆
   - 低级干扰项：简单错误

#### 风险3：省份风格识别不准确 ⚠️

**问题**：
- 风格是主观的，难以量化
- 记忆系统沉淀需要时间

**应对**：
1. **短期（MVP）**：不做省份风格
2. **中期**：用"参照真题"模式
3. **长期**：如市场验证价值，再建风格库

### 6.2 成功标准与止损点

**MVP成功标准**（阶段1结束判定）：
- ✅ 命制10道选择题
- ✅ 自我验证通过率≥70%
- ✅ 知识准确性100%
- ✅ 干扰项有效性≥60%

**止损点**：
- ❌ 如通过率<50% → 暂停开发
- ❌ 如出现知识性错误>20% → 根本问题，需重新设计
- ❌ 如3轮迭代仍无改善 → 调整策略

## 七、商业价值分析

### 7.1 核心价值主张

**对用户的价值**：

1. **降低命题成本**
   - 当前：人工命题，1道题30-60分钟
   - 使用AI：5-10分钟生成初稿 → 人工优化10-20分钟
   - 效率提升：2-3倍

2. **提升命题质量**
   - 基于教材知识库，减少知识性错误
   - 参考真题结构，规范性更强
   - 自我验证机制，质量更稳定

3. **知识沉淀**
   - 命题过程中的思考沉淀为记忆
   - 解析真题的规律应用到命题
   - 形成组织知识资产

**对生态系统的价值**：

```
命题 → 解析 → 批阅 → 反馈优化
  ↑                      ↓
  └──────────── 闭环 ──────┘

完整的试题生命周期管理
```

### 7.2 差异化竞争力

**市场上的命题工具**：
- 大多是"题库检索+简单改编"
- 缺乏对命题逻辑的深度理解
- 没有自我验证机制

**我们的优势**：
1. **解析驱动命题**：深刻理解命题逻辑
2. **自我验证闭环**：质量保证机制
3. **知识库支撑**：准确性高
4. **省份风格**（未来）：差异化能力

### 7.3 潜在市场

**目标用户**：
1. **一线教师**：日常教学练习题
2. **教研员**：单元测试、模拟考试
3. **教辅出版**：练习册、试卷
4. **教育机构**：培训题库

**市场规模估算**（粗略）：
- 历史教师：全国约20万人
- 如10%使用，2万用户
- 年费500元/人 → 1000万年收入

**注**：这只是粗略估算，实际需市场验证

|------|-----------------|----------------------|

| **投资** | 高 | 低 |

### 8.2 优势总结

**v2.0方案的核心优势**：

1. ✅ **哲学基础更深刻**
   - 不是"模仿"，而是"理解"
   - 解析↔命题的认知对称性

2. ✅ **投入产出比更高**
   - 2-3周 vs 6-8周
   - 复用 vs 新建
   - 风险更可控

3. ✅ **能力复用更充分**
   - 100%复用Analyst现有能力
   - 思维模式双向应用

4. ✅ **质量保证更可靠**
   - 自我验证闭环
   - Analyst既是命题者又是审核者

5. ✅ **生态协同更紧密**
   - 命题-解析-批阅-优化闭环
   - 一个角色，双向能力

### 8.3 保留的价值点

**v1.0中仍然有价值的部分**：

1. ✅ **真题数据的价值**
   - 未来如需系统化风格库，仍可建设
   - 但不是现在的优先级

2. ✅ **省份风格的差异化**
   - 仍然是长期目标
   - 但用记忆系统而非独立风格库

3. ✅ **参照改编模式**
   - 作为退化方案保留
   - 如从零设计质量不够

## 十、总结

### 10.1 核心洞察回顾

**用户的深刻洞察**：
> "对题目解析的过程就是命制的过程，这个背后的逻辑是互通的，我们通过这些角色的分析，无形中就形成了一种命制的风格或者命制思路。"

**战略重构的本质**：
- 不是"建不建命题专家"的问题
- 而是认识到**Analyst已经具备命题能力**
- 只需要**激活和系统化**这种能力

### 10.2 方案价值

**降维打击**：
- 别人需要两个角色（解析+命题）
- 我们只需要一个角色的双向能力

**最小投入**：
- 2-3周 vs 6-8周
- 复用 vs 新建

**最大价值**：
- 解析-命题闭环
- 自我验证机制
- 知识自然沉淀

### 10.3 关键成功因素

**技术层面**：
- ✅ Analyst的解析能力足够强（已验证）
- ✅ 教材知识库足够准确（已建成）
- ✅ 自我验证机制可行（需验证）

**战略层面**：
- ✅ 分阶段验证，风险可控
- ✅ 预期管理，不追求完美
- ✅ 退化机制，失败有Plan B

**执行层面**：
- ✅ 先手动测试，零成本验证
- ✅ MVP快速迭代，3周出结果
- ✅ 止损点明确，不盲目投入
