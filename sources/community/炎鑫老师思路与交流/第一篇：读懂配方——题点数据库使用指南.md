# 读懂配方——炎鑫老师题点数据库使用指南

> **适用对象**：英语、语文、数学学科的一线教师
> **前置要求**：无，本文从零讲起
> **核心目标**：让你能看懂题点数据库里的每一个符号，并且知道怎么用它来检查自己的教学和出题

---

## 这份数据库到底是什么

在开始之前，有一个问题需要先回答：炎鑫老师做的这些题点数据库，到底是一个什么东西？

简单说，它是一份"能力清单"。课标告诉我们学生应该达到什么水平，但课标的描述是一段一段的文字，内容笼统，界限模糊。炎鑫老师做的事情是把这些文字拆解成一个个具体的、可以单独考查的能力点，然后给每一个能力点编上号、标上它属于哪个能力维度。最终的产物就是你看到的这些数据库。

打一个比方：课标像一篇长文章，题点数据库则是这篇文章的目录加索引。有了它，你可以精确定位到"我这道题到底在考学生的哪个能力"，而不是笼统地说"这是一道阅读理解题"或"这是一道函数题"。

---

## 第一步：理解"维度"——你学科的坐标系

打开任何一份数据库，最前面都有一张"维度表"。这是整个体系的地基。

### 什么是维度

维度就是你这个学科培养学生能力的几个核心方向。不同学科的维度不同，但作用完全一样——它们构成了分析学生能力的坐标系。

数学有六个维度：

| 编号 | 维度名称 | 一句话理解 |
|------|---------|-----------|
| D1 | 数学抽象 | 从具体的东西中提炼出一般规律 |
| D2 | 逻辑推理 | 从前提推导出结论 |
| D3 | 数学建模 | 把现实问题翻译成数学语言 |
| D4 | 直观想象 | 在脑中操作图形和空间 |
| D5 | 数学运算 | 正确高效地完成计算 |
| D6 | 数据分析 | 从数据中发现规律 |

语文有四个维度：

| 编号 | 维度名称 | 一句话理解 |
|------|---------|-----------|
| D1 | 语言建构与运用 | 理解和使用语言的能力 |
| D2 | 思维发展与提升 | 分析、比较、推断、评价的能力 |
| D3 | 审美鉴赏与创造 | 感受美、理解美、表达美的能力 |
| D4 | 文化传承与理解 | 理解和传承中华文化的能力 |

英语也有四个维度：

| 编号 | 维度名称 | 一句话理解 |
|------|---------|-----------|
| 1 | 语言能力 | 听说读写的基本功 |
| 2 | 文化意识 | 对中外文化的理解和比较 |
| 3 | 思维品质 | 理解、分析、推断、评价的层次 |
| 4 | 学习能力 | 自主学习和调整策略的意识 |

### 为什么维度很重要

传统上，我们习惯按知识点来组织教学——"今天讲函数""这周练阅读理解""这单元学被动语态"。这种方式的问题在于，它告诉你"教什么内容"，但没有告诉你"培养什么能力"。

同样一道函数题，可能主要考的是数学抽象（D1），也可能主要考的是数学建模（D3），还可能主要考的是逻辑推理（D2）。如果你只按"函数"来分类，你就看不到这个差异。而维度让你看到了。

同理，同样一道英语阅读理解题，可能主要考的是语言能力（学生读不懂），也可能主要考的是思维品质（学生读懂了但推断不出来）。维度帮你区分这两种完全不同的"不会"。

## 第二步：读懂编码——题点的"身份证号"

数据库里每一个能力点都有一个编码，类似身份证号。读懂编码规则，你就能快速定位任何一个能力点。

### 数学的编码规则

数学的编码格式是：`水平.领域.题点序号.微题点序号`

举例：`2.R1.2.3` 的含义是：
- `2` = 水平二
- `R1` = 问题解决（通用）领域
- `2` = 该领域下的第2个题点
- `3` = 该题点下的第3个微题点

所以 `2.R1.2.3` 就是"水平二 · 问题解决领域 · 构建模型求解并反思改进 · 反思结果合理性并改进模型"。

### 语文的编码规则

语文的编码格式是：`学段.领域.题点序号.微题点序号`

举例：`3.R2.4.2` 的含义是：
- `3` = 第三学段（5～6年级）
- `R2` = 阅读与鉴赏领域
- `4` = 该领域下的第4个题点
- `2` = 该题点下的第2个微题点

所以 `3.R2.4.2` 就是"第三学段 · 阅读与鉴赏 · 评价事件人物与发现文本特点 · 发现不同文本的结构和语言特点"。

### 英语的编码规则

英语的编码稍有不同，格式是：`学段序号-条目序号.微题点序号`

举例：`3.7.2` 的含义是：
- `3` = 三级（7～9年级）
- `7` = 第7条课标条目
- `2` = 该题点下的第2个微题点

所以 `3.7.2` 就是"三级 · 深度阅读理解与分析 · 推断隐含信息"。

### 编码的实用价值

编码不是摆设。当你在教研中讨论一道题的时候，说"这道题考的是2.R1.2.3"比说"这道题考的是建模和反思"要精确得多。前者指向一个明确的、有课标依据的能力点，后者则可能在不同人心里指代不同的东西。编码让教研讨论有了共同语言。

## 第三步：区分题点和微题点

数据库里有两级结构：题点和微题点。理解它们的关系是正确使用数据库的关键。

### 题点是什么

题点对应课标中的一条描述。课标原文通常用一段话描述一个综合能力，比如数学课标说："在熟悉的情境中，能发现和提出有意义的数学问题，借鉴已有的解决问题思路，运用数学概念、公式、定理、模型等，进行计算或论证，得到结果，能解释结果的意义。"这整段话就是一个题点。

每个题点都标注了它的"主维度"和"关联维度"。主维度是这个能力最核心归属的维度，关联维度是在执行过程中会涉及到的其他维度。比如上面那个题点，主维度是D3数学建模（因为核心考查的是把问题翻译成数学语言的能力），关联维度是D5数学运算和D2逻辑推理（因为你还需要算对、推理正确）。

### 微题点是什么

微题点是把题点进一步拆分后的结果。拆分的标准只有一个：**能不能单独出一道题来考查它**。

比如上面那个数学题点可以拆成四个微题点：
1. 发现和提出数学问题（可以单独出题：给一个情境，问学生"你能提出什么数学问题"）
2. 运用数学工具计算（可以单独出题：给定方程，要求计算）
3. 运用数学工具论证（可以单独出题：要求证明某个结论）
4. 解释结果的意义（可以单独出题：给出计算结果，问"这个结果说明了什么"）

### 有些题点不拆

数据库里有一类题点标注了"不拆微题点（应用说明）"。这意味着这个题点已经是最小单元，无法再进一步拆分并独立考查。此时数据库会给出"应用说明"，告诉你这个能力在实际考试中以什么方式呈现。

比如数学的"1.R6.1 学习意愿与自信心"就不拆，因为"学习意愿"和"自信心"在考试中无法分别独立考查，它们属于态度类能力。

## 第四步：实际怎么用

理解了以上三步之后，你可以用题点数据库做以下几件事情。

### 用法一：检查一道题到底在考什么

拿到一道试题后，对照数据库，找到它考查的题点编码和对应的维度。这个过程能帮你看到"表面在考什么知识"背后，"实际在考什么能力"。

比如一道数学题让学生"用函数的单调性解释某个现实现象"，对照数据库可以找到它对应的是 `1.R2.2.1 用单调性等性质解释变化规律`，主维度是D3数学建模，关联维度是D1数学抽象。这告诉你：这道题的核心不是"学生会不会单调性"（那是知识），而是"学生能不能用数学语言解释现实"（那是建模能力）。

### 用法二：诊断一份试卷的能力覆盖

给一份试卷的每道题都标上题点编码，然后统计一下：这份卷子覆盖了哪些维度、哪些水平？有没有某个维度完全没有被考到？有没有某个水平被过度集中？

这个分析能帮你判断一份试卷的质量。一份好的试卷应该在维度和水平上有合理的分布，而不是集中在某几个维度或某一个水平上。

### 用法三：追踪学生的能力弱点

如果一个学生在多道题上都出错了，不要只看"他错了什么知识点"，而是看"他错的那些题在维度上有没有共性"。如果你发现他错的题大量集中在某一个维度上，那很可能这个维度就是他的瓶颈。

比如一个学生数学成绩不好，你给他错的题都标上编码，发现D1数学抽象反复出现。这就提示你：这个学生的核心问题不是某个知识点没学好，而是"从具体到抽象"这个认知能力没有建立起来。这时候多刷函数题不会有用，需要专门训练抽象能力。

### 用法四：设计教学目标

以往写教案，教学目标通常写的是"掌握函数的单调性""能正确使用一般过去时"这类知识目标。有了题点数据库，你可以把目标写得更精确：本节课的核心目标是培养学生 `1.R2.2.1` 的能力，主维度是D3建模。这样的目标不仅告诉你教什么，还告诉你培养什么能力、用什么标准衡量。

## 附：快速查找路径

如果你第一次打开数据库感觉信息量太大，建议按以下路径入手：

1. **先看"学科参数包"部分**，搞清楚你这个学科有哪几个维度、领域轴是什么。这是整个数据库的坐标系，理解了它，后面的内容就有了参照系。

2. **再看你当前正在教的那个水平/学段的"题点汇总表"**。汇总表列出了该水平所有的题点、微题点数量和所属领域，是一张快速总览图。

3. **然后针对你关心的某道具体题目，到正文中找对应的题点**。看它的课标原文、主维度、关联维度、微题点拆分，把这道题和数据库对上。

4. **最后试着给你最近出的一份试卷的每道题标上编码**，做一次完整的能力覆盖分析。这是从"看懂"到"会用"的关键一步。
