# 最近很火的「同事Skill」，其实少了一个脑子

最近朋友圈里，大家都在玩一个很有意思的东西，叫「同事Skill」（或者女娲Skill）。简单来说，就是把身边某个很厉害的同事的工作方法提炼出来，打包成一个AI技能，随时调用。

其实早在去年，我们就已经用 PromptX（一个拥有完整角色架构的系统）做过类似的事情了。当时我们集结了所有优秀同事的力量，捏出了一个「超级同事」的AI角色，让他来帮我们快速产出核心内容，大家再在这个基础上做修改，确实非常顺手。

这里我想说一说，大家可能会觉得，那到底我们捏出一个这样的「同事角色」和现在的「同事Skill」有什么区别？

如果你只是用 Skill，你会发现它其实是一个很生硬、很「死」的东西。它就像一本静态的操作说明书，里面写满了步骤，但它没有带着「脑子」。

当你需要处理的工作是高度标准化的，比如按固定格式写个周报，用 Skill 没问题。但一旦你的工作需要一点创意性、有一定的复杂性，或者需要结合具体情境去思考时，你就会发现单靠 Skill 根本推不动。

这时候，你必须引入「角色」的概念。

可能很多非技术圈的朋友对「角色」还没有概念。我们平时用的豆包、Kimi 或者 DeepSeek，背后都是一个拥有全人类知识的超级大脑。但它不认识你，你问它问题，它只能给出一个四平八稳的通用答案。

而「角色」，就是给这个超级大脑一个具体的「站位」。它知道了自己是谁，面对的是谁，应该用什么标准来判断事情。

那角色和 Skill 到底有什么本质区别？为什么我说处理复杂问题必须用角色？

这里有一个几乎没有人明说过的底层人类认知规律：**人在做事的时候，从来不会想「我现在要激活哪个技能」。**

你想想自己平时的工作状态，遇到问题时，我们的委托认知其实只有两种：
第一种是「用什么工具」，也就是我自己动手，找个趁手的家伙。
第二种是「找谁来做」，也就是把事情交给一个靠谱的人。

「激活技能」这个认知路径，在人类的日常工作里根本不存在。就像你遇到法律纠纷去找律师，不是因为你知道自己需要调用「合同审查技能」，你找律师仅仅是因为你知道「这种事该找律师」。

**[这里插入图片：B站课程截图 - 角色与Skill的核心区别，即你发我的那张图]**

如果你只做 Skill，你其实是在要求自己具备极强的「自我诊断能力」——你得先准确判断出自己现在需要什么类型的能力，然后再去调用对应的 Skill。这本身就是一种巨大的认知负担。

但如果你用的是角色，你只需要描述处境。你把遇到的麻烦说清楚，角色会用它自己的判断力来帮你处理。它背后到底调用了什么能力、组合了哪些 Skill，你根本不需要感知。

说到底，**Skill 只是角色的器官，而不是角色本身。** 你找医生看病，不需要操心他的「X光判读技能」是不是已经装载好了，你相信的是他这个人。

当你习惯了用角色去工作，你会发现效率有了质的飞跃。但走到最后，通用的AI角色依然会遇到一个瓶颈：它还是不够懂你。

这就引出了角色系统的终极形态——「数字分身」。

**[这里插入图片：B站课程截图 - 为什么最终我们需要数字分身]**

为什么我们最终都需要一个数字分身？这不仅仅是为了效率。

Sean 之前提过一个很现实的痛点：当你问一个通用的AI角色“我怎么赚一个亿”时，它会按照马斯克的标准给你做规划，建议你去名校深造、去硅谷创业。它站在悬崖对面100米的地方告诉你路怎么走，但它不知道你当下的家庭背景、教育经历和手里的资源，它不知道你连怎么走到悬崖边都不知道。

通用角色（哪怕是再厉害的专家角色）给出的建议，都是基于一个“合理的默认人设”。而数字分身解决的，是让AI**真正站在你的起点和处境里去思考**。它不需要你每次都从头解释“我是谁、我有什么限制”，它继承了你的人生履历和判断习惯，它是来帮你参谋的，而不是来给你上课的。

更深一层来看，就像傻青老师说的，苏格拉底那句“认识你自己”，是人类的本质需求。

构建数字分身，并不是简单地把你的工作方法罗列出来。在这个过程中，你必须去抽象自己的偏好，梳理自己的思维方式，弄清楚自己面对不同问题时到底是怎么做决定的。

这其实是一场借由AI技术，重新认识自己的旅程。数字分身不只是一个帮你干活的超级助理，它是一面镜子。当它越来越像你的时候，你也越来越清楚自己到底是一个什么样的人。

所以，别再只盯着那些眼花缭乱的 Skill 了。找个时间，试着去定义一个真正带着脑子、懂你处境的 AI 分身吧。
